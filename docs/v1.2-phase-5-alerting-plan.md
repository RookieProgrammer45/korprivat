# Phase 5 completeness — ops alerting and cutover runbook

**Authority:** specs/09 §12 and §13 Phase 5 (completeness added in 317a113). Acceptance: SC-8 unchanged; alerting surfaces exist for every §12 leading metric.  
**Status:** pull request open, not merged — [#40](https://github.com/RookieProgrammer45/korprivat/pull/40) on `feat/phase-5-ops-alerting`.  
**Flag:** `OPS_ALERTING` defaults off. While off, the ops-alert route responds 404 and does not query.

## What this slice does

- An admin snapshot lists every §12 leading metric.
- Inbox depth, dead-letter rate, unresolved-quarantine age, and reconciliation drift can fire only when an operator sets a threshold. Unset thresholds stay `unmeasured` and do not fire. No baseline number is invented.
- Availability certification still does not enable transactional booking (SC-8).
- The cutover runbook records how flags and webhooks are turned on later. It does not turn them on.

## Out of this slice

Vendor invitations, production certification, enabling any flag, and choosing payment-provider or commission numbers.
