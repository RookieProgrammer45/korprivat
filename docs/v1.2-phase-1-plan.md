# Phase 1 plan — Authorization and safety

**Authority:** specs/09 §1, §4, §5, §11, §13 Phase 1, §15. Runbook: [cursor-workflow.md](./cursor-workflow.md).  
**Status:** Approved by the Phase 1 execution brief (2026-10-23). Supersedes the earlier flag-only draft.  
**Branch:** `phase-1-school-authorization`

## Decisions

1. **Append-only `SchoolAuthorizationEvent`** (`grant` | `withdraw` | `admin_suspend`). Per-listing `sequence` plus `decisionVersion`. Commands are idempotent on `idempotencyKey` and rejected when `expectedHeadSequence` is stale, so a grant cannot land after a withdrawal.
2. **Grants** require a `ListingRepresentativeAuthority` row (verified representative). The listing owner is not that authority. Each grant stores actor, approved scopes, decision version, timestamp, and `evidenceRef`. Events are never deleted.
3. **`contact` stays restricted.** A grant cannot lift it. The migration writes audit notes only.
4. **`SCHOOL_AUTHZ_ENFORCEMENT`** defaults off. On: a scope must be granted. Off: legacy `bookingMode` still opens surfaces, **except** a recorded withdraw or `admin_suspend` still removes that scope (accept of a pending request included). Tests cover both states.
5. **OfferingRequest is `inquiry_collection`.** The contract is a public name/email/phone message, like the contact form, and the offerings schema calls it contact-style until checkout exists. `request_to_book` is only `POST /api/bookings` mode `request` and acceptance. General `/api/contact` is not gated.
6. **Empty new tables are safe for `prisma db push`.** No changes to existing columns. With zero `ListingOrgBinding` rows, booking create may still snapshot the legacy affiliation. As soon as a binding row exists for the listing, the snapshot is the verified active binding or null — never “first membership”.
7. **SC-19 is in this phase** (workflow done-when; the execution brief requires it). specs/09 §13’s acceptance list omitted it; the brief resolves that conflict in favor of building `ListingOrgBinding` now.
8. **Checkout** only pays an existing `bookingId`. It is a lifecycle path and is not scope-gated.

## Out of this phase

Partner certification, Hold/Allocation, versioned cancellation policy, commission copy.
