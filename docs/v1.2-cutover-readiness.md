## Blocking gap — schema is not on production

The runbook precondition “additive schema is already on production via `prisma db push`” is **false**.

Present on production: `Instructor`, `Booking`, and the older marketplace / auth tables.  
**Missing:** `SchoolAuthorizationEvent`, `ListingRepresentativeAuthority`, `ListingOrgBinding`, `CancellationPolicy`, `BookingStateTransition`, `PaymentRecord`, `OpsTask`, `SchoolConnection`, `BookingEvent`, `CommandOutbox`, `Partner`, `Certification`, and every acquisition table (`ListingProspect`, `TeachingPermission`, `CategoryOffering`, `ConciergeDraft`, …).

`_prisma_migrations` ends at `20261015110000_add_offerings`. Phase 1–5 and ACQ migrations are not recorded.

`loadFoldedAuthorization` talks to `prisma.schoolAuthorizationEvent` when the generated client has that delegate. After a deploy that includes the new client, a flag-on request would query a table that does not exist and fail the request — not fail closed to directory-only.

**Do not flip any flag until this schema gap is resolved by an authorized additive apply.** This report does not apply it.

`existingBookingLifecycleAllowed()` is always true. Cancel, refund, dispute, support, and checkout of an **existing** booking stay open after a withdrawal or a flag flip.

| Omar Nasser (`instructor_omar`) | instant | `cancelled_full_refund` | 1 |

There are **no confirmed, unpaid, or paid live bookings**. There is nothing whose cancel/refund path would need to stay warm at flip. New bookings from the 634 schools would be refused (`not_authorized_by_school`) once the flag is on and no grants exist.

- A documented grant exists for every school that should stay bookable. Legacy `bookingMode` is not a grant.
- Contact count stays 1 (Sjöbo Trafikskola).

## Rehearsal method (test environment)

`scripts/run-cutover-rehearsal.ts` sets each flag to `1` only in the child Vitest process, runs `vitest run`, then `vitest run -t SC-`. It does not call Vercel or Neon.

**Gap:** many unit tests `delete process.env.<FLAG>` in `beforeEach`. A green suite with the flag exported does **not** prove every route under a process-wide production flip. Tests that already name `SC-1`…`SC-25` cover the flag-on cases they opt into. Step 1 is the exception: those route tests leave the env var in place, so the gate actually ran.
