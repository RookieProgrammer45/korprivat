## 4. Data model — existing vs new (§11)

### Existing (verified)

| Entity | Location |
| --- | --- |
| User / Session / Account | [`prisma/schema/auth.prisma`](../prisma/schema/auth.prisma) |
| Instructor, Booking, AvailabilitySlot, PayoutRecord | [`prisma/schema/instructors.prisma`](../prisma/schema/instructors.prisma) |
| Organization, Membership, MembershipInvite | [`prisma/schema/organizations.prisma`](../prisma/schema/organizations.prisma) |
| InstructorLicense | [`prisma/schema/instructor-license.prisma`](../prisma/schema/instructor-license.prisma) |
| Dispute (escrow) | [`prisma/schema/escrow.prisma`](../prisma/schema/escrow.prisma) |
| LateCancellationFee | [`prisma/schema/cancellation.prisma`](../prisma/schema/cancellation.prisma) |
| StripeWebhookEvent | [`prisma/schema/stripe-webhook-event.prisma`](../prisma/schema/stripe-webhook-event.prisma) |
| DiditWebhookEvent, VerificationEvent | [`prisma/schema/verification.prisma`](../prisma/schema/verification.prisma) |
| BookingReceipt, reviews, messaging, handledare, waitlist, etc. | under [`prisma/schema/`](../prisma/schema/) |

**School mapping (canonical today):** a school listing is an `Instructor` row with `providerRole` school/instructor semantics; link to org is **User → Membership → Organization** via nullable `Instructor.userId`. There is **no** `Instructor.organizationId`. Bookings snapshot `organizationId` at create via [`getActiveAffiliationForUser`](../src/lib/orgs/public.ts) in the bookings route (first ACTIVE membership by `createdAt` — ambiguous with multiple memberships; SC-19 gap).
